# 📚 Книжный интернет-магазин 

Проект представляет собой современное Fullstack-приложение интернет-магазина книг, оформленное минималистичным дизайном страниц и обложками товаров. Проект реализован на монолитной архитектуре с использованием экосистемы **FastAPI**, **SQLAlchemy** и асинхронного фронтенда на **JavaScript/Jinja2** (Jinja2 - Динамичный шаблонизатор, удобно используемый для HTML-страниц. Он подставляет данные прямиком из кода)
Асинхронный фронтенд - подход к разработке пользовательских интерфейсов (веб-страниц и приложений), при котором длительные операции выполняются в неблокирующем режиме. Пользователь может свободно прокручивать страницу, нажимать на кнопки и взаимодействовать с сайтом, пока идет загрузка.

---

## 🚀 Технологический стек

* **Backend:** Python 3.11+, FastAPI, Pydantic
* **Database & ORM:** SQLite, SQLAlchemy 2.0 (Declarative Mapping)
* **Frontend:** HTML, CSS Grid, Jinja2 Templates, JavaScript (Async/Fetch API)
* **Web Server:** Uvicorn

## Архитектура проекта и обоснование решений

### 1. База данных и ORM (SQLAlchemy 2.0)
Вместо написания сырых SQL-запросов использовалась ORM SQLAlchemy в современном декларативном стиле (`Mapped[...]`). Это решает сразу несколько задач:
* **Безопасность:** Автоматическая защита от SQL-инъекций.
* **Связи таблиц (Relationships):** В таблице корзины (`Cart_obj`) настроена связь `relationship("Book_obj")` с таблицей книг через внешний ключ (`ForeignKey`). Это позволило выводить в корзине реальные названия, цены и обложки книг, а не безликие ID, прямо через объект связи `item.book.title`.

### 2. Структура сущностей (Модели данных в `models.py`)
* `Book_obj` (`Books`) — хранит данные книг (название, автор, год, жанр, цена, путь к обложке).
* `Reader_obj` (`Readers`) — профиль читателя (имя, контакты, дата регистрации, динамический баланс счета).
* `Cart_obj` (`Cart`) — связующая таблица корзины со счетчиком количества книг (`quantity`).
* `Promo_obj` (`Promocodes`) — скидочные купоны со встроенным сроком годности.
* `Buy_obj` (`Purchases`) — логируемая история успешных заказов для финансовой отчетности.

### 3. Управление сессиями (Менеджер зависимостей `get_db`)
Функция-генератор `get_db()` используется как зависимость `Depends(get_db)` в каждом эндпоинте:
* **Почему так:** Она реализует паттерн *Dependency Injection*. Открывает изолированную сессию соединения с БД в начале запроса, передает её эндпоинту через `yield`, а после отправки ответа гарантированно закрывает её в блоке `finally`. Это предотвращает утечки памяти и блокировки файлов SQLite.

### 4. Формы и асинхронный фронтенд (FastAPI Form + JavaScript Fetch)
Изначально отправка промокодов и оплата выполнялись стандартными HTML-формами, что уводило пользователя на «черный экран» со строками JSON. Проблема была решена связкой `FastAPI Form(...)` и асинхронного **JavaScript API (Fetch)**:
* **Почему так:** JS перехватывает событие отправки формы (`e.preventDefault()`), отправляет запрос на бэкенд в фоновом режиме, обрабатывает JSON-ответ и на лету меняет элементы интерфейса (выводит скидку, пересчитывает «Итого к оплате», выводит сообщения об ошибках), предотвращая перезагрузку страницы. Это соответствует стандартам коммерческого UI/UX. Это не нагружает страницу и мгновенно показывает результат, в данном случае это либо ввод промокода или рассчёт суммы скидки.

## 💡 Разбор ключевой бизнес-логики (Эндпоинты)

### 🛒 Добавление и удаление из корзины
* `POST /cart/add?book_id={id}&reader_id=1` — создает запись в таблице `Cart`. Реализован автоматический редирект (`RedirectResponse` со статусом `303 See Other`) обратно в интерфейс корзины для мгновенного отображения добавленной книги.
* `POST /cart/delete/{item_id}` — находит запись в таблице по уникальному первичному ключу (`db.get`), удаляет её и возвращает пользователя в обновленный список.

### 🎟 Система промокодов (`POST /cart/promo`)
Эндпоинт принимает код и текущую сумму корзины. Внутри реализован каскад строгих проверок:
1. Проверка существования кода в БД (с автоматическим приведением регистра через `.upper()`).
2. Проверка флага активности купона (`promo.active`).
3. Валидация срока годности (`datetime.now() > promo.expires_at`).
Если все условия выполнены, бэкенд вычисляет скидку и отдает фронтенду новый баланс.
(Доступен пользования в качестве тестирования только один промокод, SALE100)

### 💳 Симуляция эквайринга и покупки (`POST /purchase`)
Самый сложный узел приложения. При нажатии «Оформить и купить»:
1. Из базы вытаскивается актуальный баланс читателя (`reader.balance`).
2. В цикле рассчитывается итоговая стоимость всех книг, лежащих в корзине данного пользователя.
3. Проверяется условие достаточности средств. Если денег мало или корзина пуста — FastAPI выбрасывает ошибку `HTTPException(status_code=400)`, которую JS выводит красивым красным текстом под кнопкой.
4. При успехе: деньги списываются со счета читателя, создается запись в логе покупок (`Buy_obj`), корзина пользователя **полностью очищается** (`db.delete(item)`), а JS перенаправляет пользователя на страницу успеха.

## 🎨 Особенности интерфейса (Стилизация)

* **Базовый каркас (`base.html`):** Применен паттерн наследования шаблонов Jinja2 `{% extends "base.html" %}`. Верхнее навигационное меню (оформленное в виде стильной скругленной капсулы-рамки) и структурированный футер («подвал» сайта) прописаны один раз, избавляя от дублирования кода.
* **Двухрядная корзина (`cart-list`):** Список выбранных товаров в корзине переведен на сетку `CSS Grid`, которая на больших экранах автоматически выстраивает карточки в два симметричных ряда, экономя пространство.
* **Изюминка функции покупки:** Страница успешной оплаты (`/purchase/success`) снабжена изображением и текстом благодарности, что повышает лояльность пользователя.

## Запуск проекта локально

1. Зависимости:
   ```bash
   pip install -r requirements.txt или pip freeze > requirements.txt 
   ```
2. Запуск проекта:
   ```bash
   uvicorn main:app --reload
   ```
3. **Важно:** Нужная команда для запуска:
   ```bash
   python seed.py
   ```
4. Браузер: `http://127.0.0`
